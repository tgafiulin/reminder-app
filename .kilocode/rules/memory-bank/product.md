# Product

## 1. Зачем существует проект

Remindy — персональное веб‑приложение центр управления делами, поездками и личными задачами. Оно помогает:

- быстро фиксировать идеи и события;
- хранить связанную информацию (заметки, ссылки, медиа);
- настраивать напоминания по времени;
- группировать напоминания по контекстам/темам;
- отслеживать статус выполнения задач;
- готовить данные к более сложным представлениям (календарь, таймлайн).

Сейчас это полностью клиентское приложение без собственного backend, ориентированное на личное использование и отработку архитектурных подходов фронтенда.

## 2. Пользовательские сценарии (MVP)

### 2.1. Работа с напоминаниями

Пользователь может:

- создать напоминание с полями:
  - заголовок (обязательное поле);
  - описание (опционально);
  - ссылка на медиа (опционально);
  - дата и время срабатывания напоминания;
  - контекст/тема для группировки (опционально);
- просматривать список всех напоминаний, сгруппированных по контекстам;
- редактировать существующее напоминание;
- удалять напоминание;
- отмечать напоминание как выполненное или активное;
- управлять списком контекстов через модальное окно (создание, редактирование, удаление).

### 2.2. Хранение и восстановление данных

- Напоминания хранятся в localStorage под ключом `remindy:reminders`.
- Контексты хранятся в localStorage под ключом `remindy:contexts`.
- При загрузке приложения:
  - данные читаются из localStorage;
  - выполняется безопасное восстановление (защита от битых или неожиданных данных);
  - пустое или некорректное состояние не ломает UI;
  - для старых записей без поля `status` устанавливается значение `"active"`.

### 2.3. Напоминания по времени

- Для напоминаний с валидным полем `remindsAt` рассчитывается задержка до срабатывания.
- Хук планировщик выбирает ближайшее активное напоминание в будущем и ставит таймер.
- При наступлении времени:
  - показывается браузерное уведомление с заголовком и описанием напоминания;
  - уведомление не исчезает автоматически (`requireInteraction: true`);
  - при клике на уведомление окно приложения получает фокус.

### 2.4. Управление контекстами

Пользователь может:

- создавать новые контексты через модальное окно управления контекстами;
- редактировать существующие контексты (переименование автоматически обновляет все связанные напоминания);
- удалять контексты (удаление очищает поле `context` в связанных напоминаниях);
- выбирать контекст из списка при создании или редактировании напоминания.

### 2.5. Браузерные уведомления

- Приложение запрашивает разрешение на показ уведомлений через баннер.
- Баннер можно скрыть (состояние сохраняется в localStorage).
- Если разрешение отклонено, пользователю предлагается включить уведомления через настройки браузера.

## 3. Как приложение должно работать с точки зрения UX

- **Минималистичный интерфейс**:
  - одна основная страница напоминаний;
  - слева форма создания напоминания;
  - справа список напоминаний, сгруппированный по контекстам.
- **Прозрачные статусы**:
  - визуальное различие активных и выполненных напоминаний (зачёркнутый текст, бейдж "Выполнено");
  - чекбокс для быстрого переключения статуса.
- **Простота редактирования**:
  - редактирование происходит прямо в карточке напоминания;
  - поля в режиме редактирования повторяют структуру формы создания;
  - локализованные подписи и тексты на русском языке.
- **Управление контекстами**:
  - кнопка с иконкой настроек рядом с полем контекста;
  - модальное окно для управления контекстами;
  - автодополнение при вводе контекста.
- **Надёжность**:
  - некорректные даты игнорируются без ошибок в интерфейсе;
  - хранение в localStorage не должно ломать приложение при плохих данных;
  - перезагрузка страницы не приводит к потере валидных напоминаний;
  - миграция данных для старых записей (добавление `status`).

## 4. Будущее развитие продукта

### 4.1. Расширение представлений

Планируется добавить:

- календарные представления (месяц, неделя, день);
- таймлайны для событий и поездок;
- фильтрацию и сортировку напоминаний по различным критериям.

### 4.2. Синхронизация и совместная работа

В будущем:

- подключение backend (например, Supabase или собственный API);
- авторизация и мульти‑устройство;
- опционально совместный доступ к наборам напоминаний.

### 4.3. PWA и офлайн

- поддержка установки на домашний экран;
- базовый офлайн‑режим;
- кэширование основных ресурсов и локального состояния.

### 4.4. Расширение доменной модели

- приоритеты напоминаний;
- теги для более гибкой классификации;
- вложенность задач (подзадачи);
- повторяющиеся напоминания.

## 5. Цели по качеству и архитектуре

- Строгая типизация и чистые интерфейсы типов для домена напоминаний.
- Чёткое разделение ответственности:
  - UI слой (страницы и компоненты);
  - доменные хуки и логика планирования;
  - слой хранения (localStorage и в будущем API).
- Архитектура, готовая к:
  - появлению нескольких доменных фич поверх напоминаний;
  - выносу хранилища из localStorage во внешний сервис без ломки UI;
  - добавлению новых представлений (календарь, таймлайн) без переписывания существующей логики.
